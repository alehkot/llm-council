Runtime flow

One consultation is a gated pipeline, not one giant prompt.

Feature flags and interactive checkpoints decide which nodes run. The happy path is: collect model answers, optionally critique them, rank them anonymously, optionally let models revise, then ask the chairman model to synthesize.

What the chairman actually synthesizes

Stage 3 does not simply reread raw Stage 1. When deliberation exists, the revised deliberation answers become the main response body sent to the chairman.

User query

The original prompt, or the refined prompt when prompt refinement chose to use it.

Responses for synthesis

Usually deliberation-revised answers. A mode-aware packer decides how much of each answer is included.

Stage 2 rankings

Aggregate rankings plus compact final ranking lines from reviewers.

Negative analysis

Optional gap scores and reviewer summaries. Higher gap score means the answer addresses concerns better.

Prompt modifier

Optional synthesis preference, focus areas, and decision-support guidance when that path is active.

Chairman model

The chairman still receives one assembled prompt, but response and ranking evidence is packed first. The prompt asks for a complete answer to the original question, not a recap of the council process.

Response section Named RESPONSES FOR SYNTHESIS - Deliberation Revisions when deliberation output is used; otherwise named STAGE 1 - Individual Responses. The section can contain full-priority text or compact excerpts.
Ranking section Includes aggregate ranking summary and compact final ranking lines, with rationale excerpts only for modes that benefit from them.
Negative section Included only when Negative Mode ran. With deliberation revisions, it is framed as a pre-deliberation checklist to verify, not unresolved criticism to repeat.
Additional guidance Where synthesis mode and focus areas appear when that path injects them.

Compatibility note

The function argument is still named stage1_results for compatibility, but the prompt heading now changes when the content is deliberation-revised.

Synthesis modes

Synthesis modes now control context packing and prompt guidance.

Each mode changes which artifacts get full space, which get compact excerpts, and how much peer-review rationale is forwarded. The chairman still makes the final judgment; the app does not mechanically assemble the answer.

Mode Instruction What is algorithmic? Practical effect
Consensus Find and present only common ground. Filter out minority or contested claims. All responses use compact evidence; ranking rationale is omitted. Produces a narrower answer focused on agreement across responses.
Best of Breed Pick the best elements from each response: clear explanations, examples, and caveats. Top-ranked responses get full-priority space; others keep high-signal excerpts. Scavenges useful pieces while spending more input budget on stronger answers.
Comprehensive Include all perspectives, contradictions, trade-offs, and alternatives. Every response receives broad space, subject to the global context budget. Preserves more disagreement, alternatives, and rationale.
Weighted by Rankings Prioritize higher-ranked responses. Lower-ranked responses contribute less. Aggregate rankings reorder and allocate context budget; no numeric content blend. Leans harder on responses that Stage 2 ranked highly.

Real data path hard

Stage 2 aggregate rankings and Negative Mode aggregate gap scores are computed data structures.

Mode behavior mixed

Mode selection does reorder and compact context, but final prose is still chairman judgment.

Exclusions hard

Interactive response exclusions are applied to active Stage 1 inputs before ranking, deliberation, and synthesis.

Resynthesis

Regenerating a synthesis appends a new Stage 3 version.

Resynthesis does not rerun Stage 1, Stage 2, Negative Mode, or deliberation. It reuses the existing persisted evidence, repacks the synthesis context for the selected mode, and asks the chairman for another final answer with new guidance.

1. Pick mode

The UI sends a requested synthesis mode and optional focus areas.

2. Rebuild input

build_responses_for_synthesis prefers deliberation revisions if present.

3. Pack context

The backend applies mode-specific response, ranking, and negative-summary budgets.

4. Run chairman

The chairman receives the packed context and writes a new final answer.

5. Append version

The new answer is added to stage3.versions and can become current.

Current caveats

Implementation truths worth keeping in mind

These are not necessarily bugs, but they explain why the UI can feel less deterministic than the stage labels imply.

Deliberation is explicit

Stage 3 receives revised answer text after deliberation and labels the response section accordingly. Negative Mode is treated as a checklist against those revisions.

Weighted is not numeric

The app computes rankings, but the weighted mode does not mechanically blend answers by score. It uses rankings to spend more context on top-ranked responses, then instructs the chairman to favor them.

Initial and resynthesis share packing

Both the initial LangGraph run and explicit resynthesis path call the same Stage 3 context packer, so mode behavior is consistent.
